# site-diag

**一个单文件、免安装的 Windows 命令行工具，用来说清「网站打不开」到底卡在哪一段。**

「打不开」通常只被当成一个现象上报，但它至少有四个完全不同的责任方：这台电脑、公司出口、
运营商、网站自己。`site-diag` 跑六组检测，把结果互相对照，最后直接给出结论、责任方和处理建议，
而不是丢一堆原始输出给你自己看。

[English](README.md)

```
==================================================================

==================================================================

[1/6] 本机环境
  hosts 文件             无相关记录
  系统代理               未启用
  本机 DNS 服务器        223.5.5.5, 114.114.114.114
  出口公网 IP            203.0.113.24   （报障时必填）

[2/6] 域名解析
  本机 DNS               203.0.113.9
  阿里 223.5.5.5         203.0.113.9

[3/6] 连通性

  TCP 80                 连通  27 ms

[4/6] HTTPS 握手：带域名 / 不带域名
  带域名握手             成功  Tls12（3 次里成功 2 次）
  证书校验               通过（与浏览器一致）

[5/6] HTTP 返回
  80 端口                HTTP/1.1 301 Moved Permanently
  443 端口               HTTP/1.1 200 OK

[6/6] 浏览器路径（走系统代理 / PAC，和浏览器尽量一致）

==================================================================
  结论：未发现链路阻断，网站可以正常访问
```

## 为什么做这个

「网站挂了」几乎是所有报障的第一句话，然后第一小时都花在补基本事实：DNS 通不通、TCP 通不通、
TLS 能不能握手、浏览器走的是不是和 `curl` 同一条路。

`site-diag` 把这个「第一小时」自动化。它刻意做成**相关性工具**而不是抓包工具：价值在检测项的组合，
不在任何单独一项。

## 六组检测

| # | 检测 | 用来区分什么 |
|---|------|-------------|
| 1 | 本机环境 | `hosts` 改写、系统代理、PAC、VPN / 零信任客户端、配置的 DNS |
| 2 | 域名解析 | 本机 DNS 与阿里、腾讯、114、谷歌四路对照，一家不同就是强信号 |
| 3 | 连通性 | ICMP、TCP 443、TCP 80 及耗时 |
| 4 | HTTPS 握手 | 同一 IP **带 SNI** 与**不带 SNI** 各握手，连试三次，并真正校验证书 |
| 5 | HTTP 返回 | 状态行、`Location`、`Server`，用于识别跳转式拦截页 |
| 6 | 浏览器路径 | 用 `HttpWebRequest` 走系统代理 / PAC，即浏览器实际走的那条路 |

第 4 组是核心思路：如果**不带域名**的握手成功、**带域名**的失败，说明路径上有人读了域名后掐连接 ——
这是域名层阻断，和 IP 层阻断是完全不同的两件事。

第 6 组是为了避免另一类误判：原始 socket 可以绕过代理和零信任客户端，而浏览器绕不过，
所以「工具说通、浏览器打不开」是真实且常见的结果。两条路径都测，然后对比。

## 快速开始

从 [Releases](../../releases) 下载 `site-diag.exe`，或者自己编译（见下）。

```
site-diag.exe                      # 交互模式，提示输入域名
site-diag.exe example.com          # 跑一次
site-diag.exe https://example.com/path?q=1
site-diag.exe example.com --lang zh
```

第一屏就是语言选择，中英文同时显示：

```
  Select language / 请选择语言

    1)  English
    2)  中文

  Press Enter for English.
```

默认英文 —— 看不懂中文的人不会卡在第零步；中文用户输入 `2` 回车即可。

## 结论对照

| 结论 | 责任方 |
|------|--------|
| 未发现链路阻断 | — |
| 域名解析被篡改 | 运营商 DNS / 公司内网 DNS |
| 域名解析不出来 | 域名 / DNS 记录 |
| hosts 文件被手工改过 | 本机 |
| 目标 IP 不可达 | 运营商 或 公司出口设备 |
| IP 可达但端口不通 | 运营商 / 防火墙 / 服务器 |
| 域名层阻断：通 IP、不通域名 | 运营商 或 公司出口设备 |
| 间歇性阻断：时通时不通 | 运营商链路 / 限流 |
| 证书不可信 | 中间人 或 证书本身 |
| 直连通、浏览器路径被拦 | 本机代理 / VPN / 零信任客户端 |
| 服务器或 CDN 拒绝了出口 IP（403） | CDN / 源站 WAF |

## 退出码

| 码 | 含义 |
|----|------|
| `0` | 正常，未发现阻断 |
| `1` | 发现问题 |
| `2` | 用法错误，或证据不足 |

脚本里可以直接用：`site-diag.exe example.com --lang zh || 告警`。

## 从源码编译

环境要求：Windows 7 SP1 及以上，.NET Framework 4.5+。`csc.exe` 随框架自带，
不需要 SDK、不需要 NuGet、不需要 Visual Studio。

```bat
build.bat
```

或者手动：

```bat
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe ^
  /target:exe /out:site-diag.exe /win32icon:assets\site-diag.ico ^
  /codepage:65001 /optimize+ src\Net.cs src\Program.cs
```

每次 push 都会在 `windows-latest` 上自动构建；推送 `v*` 标签会自动把二进制挂到 Release 上。

## 隐私

没有遥测、没有统计，除了下面三类请求之外不联网：

* 向上面那几个公共 DNS 服务器发解析请求；
* 向**你输入的**主机发 TCP / TLS / HTTP 请求；
* 一次明文 HTTP 请求到 `ip.3322.net`（备用 `myip.ipip.net`），用来显示出口公网 IP。

结果只写本地 `site-diag-<域名>-<时间>.txt`，不发往任何地方。

## 首次运行：SmartScreen 提示

发布的二进制没有代码签名，所以**下载来的**副本第一次运行时，Windows 可能弹「Windows 已保护你的电脑」。
这是信誉提示，不是病毒判定 —— 真实原因是浏览器/邮件客户端在下载时给文件写了一个 NTFS
`Zone.Identifier` 数据流（“来自 Internet”标记）。**没有这个标记就不会弹**：同样的字节在本机编译出来，
双击是静默运行的。

| 做法 | 怎么操作 | 适用 |
|------|---------|------|
| 直接放行 | 点「更多信息」→「仍要运行」 | 就这一次 |
| 去掉标记（推荐） | 右键 → 属性 → 勾选**解除锁定**；或 `unblock.bat site-diag.exe`；或 PowerShell 里 `Unblock-File` | 这个文件，永久有效 |
| 本地编译 | `build.bat`，本机生成的 exe 永远不带这个标记 | 要铺到很多台机器 |

用 U 盘、内网共享、企业微信传过去的副本，通常也不带这个标记。

要让**所有人**都不再看到提示，只有买 EV 代码签名证书一条路，一年几百美元 —— 内部工具基本不值当。

## 局限

* 仅 Windows，主要面向 IPv4。
* 看不到 QUIC / HTTP3（UDP 443）。如果浏览器打不开而本工具正常，先关掉浏览器的 QUIC 再试。
* 很多 CDN 会丢弃 ICMP，所以 `ping 不通` 只作为参考信息显示，不单独判定为故障。
* 本机 Schannel 组件异常导致的 TLS 失败会明确标注为「本机问题」，不会甩锅给网络。
* 发布的二进制没有代码签名，首次运行会有 SmartScreen 提示；介意的话用 `build.bat` 本地编译。
